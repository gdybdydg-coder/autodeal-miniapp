## Три незалежні відтворені дефекти та виправлення

1. **Переповнення помилково фіналізувало дедуплікацію.** Collector додавав ID
   до `seen` перед перевіркою MAX_QUEUE. Відкинута подія не могла потрапити до
   черги при наступному спостереженні, навіть після звільнення місця і restart.
   Тепер дата записується лише після прийняття до bounded queue або наявності
   існуючого job. Повторна спроба можлива лише за нового дозволеного snapshot,
   поки подія свіжа; backlog старого каталогу не створюється.
2. **Dedup collector порівнював тільки ID.** Після відхилення до створення job
   новіший genuine add-date під тим самим ID ігнорувався. Тепер порівнюються
   дати: та сама/старіша дата залишається dedup, новіша допускає перевірку з
   усіма чинними guards. Існуючі jobs/seen/claims не видаляються та не
   перевикористовуються. Update-only, raise/reprice і просто поява не доказ.
3. **Preview price блокувала перевірку current price.** Наприклад, збережений
   діапазон $1000–7000, preview $10000, офіційна актуальна ціна $6000: усі
   targets відкидалися до info API. Тепер price bounds застосовуються до
   перевіреної актуальної ціни через existing `matches`. Якщо вона $8000 або
   $500, авто все одно не проходить. Відсутність нової дати публікації не
   запускає перевірку через зміну ціни.

Відтворювані тести використовують справжні локальні monitor/dispatcher шляхи,
SQLite fixtures і підставні source/quote/sender. Перед виправленням позитивні
сценарії кожного дефекту падали; після виправлення три позитивні проходять.
Додано два негативні варіанти актуальної ціни, bounded queue і restart,
відхилення update-only, відсутність зайвої оцінки та спільний quote.

## Незмінні правила та обмеження

Primary paid search і його cadence не змінені. Active window не ввімкнено.
Collector залишається двосторінковим, MAX_AGE 3600, MAX_QUEUE 128,
MAX_SEEN 10000; HTTP reservations/robots/backoff і API caps 200/h, 1000/day,
20% primary headroom та global ledger залишені. Офіційні деталі підтверджують
passenger category, active/positive current price, add-date, filters, current
epoch. Missing optional/damage не стають причиною відсіву. Abroad/custom,
minDiscount, official AI lower_bound*.95, confirmed-only, /stop та claims
збережені; формула клієнтам не додається.

Відмова від preview-відсіву може збільшити info-запити в межах тих самих caps.
Це виправлення охоплення, а не доказ економії чи всіх знайдених оголошень.
Повні сторінки, expiry, quota/HTTP denial, existing job і відсутність доказу
справжньої нової публікації залишаються причинами втрат/відсіву. Черга не може
відновити оголошення, що зникло з двох sampled pages.

## Перевірки та наступний крок

Повний повторний прогін з network fence:
`python -m pytest backend/tests experiments/free_search/tests -q` — **1097 passed,
110 subtests passed, 1 warning, 139.98 s**, exit 0. Існуюче попередження
Starlette/httpx не пов'язане зі зміною. Успішний прогін не мав непідставлених
мережевих спроб: strict guard також перевіряє I/O, приховане винятками.
Початковий перерваний прогін не зарахований як перевірка. Нові тести охоплюють
два механізми collector, три варіанти current price і п'ять перевірок fence.

Чинний Render повторно перевірено перед GitHub записом: deployment
`dep-daumfo59fdbs739haga0` лишається live на тому самому main. WIP head перед
записом той самий e11f97f0; update виконується без force. Цей commit змінює
лише recent_publications, його тести/опис, command-test fixture та offline
test guard; наступний main переносить лише цей diff за окремим дозволом,
а не весь нічний прототип.
Нічний безкоштовний прототип не інтегрується в backend цією зміною; для нього
джерело/оцінка та дозвіл на безперервне використання ще не підтверджені.

Перед будь-яким майбутнім впровадженням потрібен явний дозвіл користувача
змінити чинний платний бот. Підтвердити точний diff/tested tree, повторно
перевірити main і Render, не створювати duplicate deployment. Далі перевірити
цільові add-date/owner trace для BMW/Audi/Kangoo дозволеним персональним
діагностичним шляхом та виміряти coverage на нових публікаціях. Не робити
масове recovery, не поновлювати shadow і не обіцяти whole-market recall.
