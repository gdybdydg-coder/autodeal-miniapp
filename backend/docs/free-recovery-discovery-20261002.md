## Previous work restored, not claimed as new

Historical remote commit `ab3feed090c030d4b1be33b6626611796623c3fe` (local `2fd2718`) and its current-base rebase `289adc1`/review `9aa3bd5` contain the same four proposed fixes. These changes were absent from the current live-source tree:

- Current official details, not a stale public preview price, determine price-filter eligibility.
- A genuinely newer source addition date can revisit a rejected ID; a price/update-only change cannot.
- Transient quote errors retain pending interests across restarts, with a bounded three-failure/600-second retry window. Exhaustion stays `unvalued` with the failure and count. Quota/lease pauses do not finalize a valuation.

## New defects reproduced and fixed in this session

1. **Quota pauses consumed detail retries.** `recent_publications.take` incremented attempts before source quota/lease checks, then discarded a candidate after the third pause even if no detail call occurred. Four synthetic pause types now preserve the pending candidate with zero consumed failures; recovery after restart performs one shared detail and quote.
2. **Malformed/transient detail data could be permanently discarded.** `invalid_response` previously bypassed retry, and exhausted connection/upstream failures lost item-level evidence. Genuine transient failures now have controlled 60/120-second backoff and three failures maximum. Exhaustion is a durable `MonitorJob(state='unresolved')`, without `MonitorSeen`, confirmed proof or a notification. Permanent unreadable outcomes are retained similarly; explicit sold/unavailable listings remain rejections.
3. **Expired pending evidence was lost.** Both intake expiry and collector pruning now retain `details_expired` records without requesting old cars or creating delivery claims. Status reports aggregate unresolved-detail count and oldest pending admission time. A savepoint handles a concurrent primary insertion of the same source ID without replacing primary evidence or aborting the collector transaction; its unique-conflict regression failed before the guard and passed after it.
4. **A zero preview price eliminated a listing before authoritative details.** The public preview is now unknown; the fresh authoritative parser still rejects nonpositive current prices. This does not relax current price validation.
5. **An absent cached filter dictionary became a false no-recipient decision.** `catalog_not_cached` now defers the candidate without consuming retries or issuing a paid dictionary call. Partial dictionary resolution also waits before fixing the shared recipient set.
6. **Delivery batch barrier delayed unrelated recipients.** The production dispatcher waited for all four sender threads before admitting a fifth job. A regression blocked one sender and proved the fifth/sixth could not start. Four independent bounded loops now let available slots progress; a separate queue builder runs at most once per second. Per-worker pacing remains at least 250 ms per delivery job (at most 16 jobs/second before HTTP latency), with existing per-chat limits and immediate access checks. One job may include a known-rejected-photo/text fallback; this is not a promise of 16 physical HTTP calls/second.

New tests: `test_intake_recovery.py`, `test_delivery_dispatch_recovery.py`, `test_discovery_access_delivery.py`. The first ten intake regressions failed on the baseline; missing dictionary and delivery barrier also failed before their fixes. All passed after fixes. Four additional access tests verify the current implementation, not newly invented payment changes: active access works, exact expiry at send blocks only that user, newly committed access is read by the next queue check, and payment never resumes `/stop`.

7. **Quote retry could overwrite a concurrent primary promotion.** Independent review reproduced a public-intake job promoted by primary discovery while its quote was in flight. Saving transient retry evidence incorrectly restored the old HTML origin with new primary proof, so the next attempt was cancelled. The retry save now preserves the current primary origin as `complete()` already did. The new regression fails before the guard and verifies recovery after restart even when supplemental intake is subsequently disabled.

## Verification and limits

A focused combined run passed **200 tests** in 80.76 seconds: intake, quote retries, primary pagination/catch-up, parallel discovery, monitor, confirmed-only policy, photo fallback, failed-delivery handling, subscriptions at delivery and the independent dispatcher. The subsequently expanded missing-catalogue test passed both complete and partial cache-miss cases. A separate regression proves that fresh primary discovery reopens an unresolved job and preserves its earlier detail failure/count after successful evaluation. The billing TestClient test now explicitly stubs the bot command background worker, with its network fence unchanged; the formerly blocked-DNS test passes. The final focused intake/access/dispatcher/quote retry run passed 28 tests, including the concurrent promotion, retained-error recovery and unique-conflict cases. One existing Starlette/httpx deprecation warning remains.

The 274-test exploratory run additionally exercised current billing/manual approval regressions; 272 passed before the intended sold/zero-price assertions were updated, and an existing billing TestClient test was caught attempting DNS because its current bot command background loop was not stubbed. The network fence blocked the attempt. Do not report that exploratory run as entirely green. The root integration run owns the eventual full-suite result.

All source and Telegram responses were synthetic. `backend/tests/conftest.py` blocks external DNS and sockets; no real API keys or real paid API calls were used. This environment also hangs for the independent minimal example `asyncio.run(asyncio.to_thread(lambda: 42))`. The opt-in test runner `tools/offline_pytest.py --sandbox-wakeup` (initially exercised as `/tmp/autodeal-pytest-wakeup.py`) caps selector sleeps at 50 ms to work around missing sandbox thread wakeups; it does not replace worker logic, callbacks, locks or fixture transports, and is not production code.

Already-existing primary tests cover 117 new cars over three pages and restart, deletion shifting pagination, a new head outside a frozen window, late indexing within 600 seconds, old IDs with genuinely new publication times, multiple recipients, missing optional attributes and damaged cars. These are existing tests rerun in this session, not new measured live completeness.

The primary publication window and 600-second overlap are unchanged. Supplemental public intake still has two dated pages, 128 pending slots and a one-hour age bound. Overflow recovery requires the item to remain visible in a later permitted snapshot; no completeness beyond those boundaries is claimed. Error retention records unknown outcomes rather than converting them to successful checks. `unresolved` records require investigation; they do not replay old listings. A later genuine primary discovery can reopen the source ID under the existing activation and delivery rules; this path is regression-tested and retains prior detail failure evidence. Supplemental intake alone still skips any existing unresolved job, including a newer addition date under that ID. Automatic rearming of unresolved supplemental-only republications is not implemented; it would require preserving per-event history and separately reviewing rearm policy.

No tariff, subscription implementation, filter semantics, 5% reference-price adjustment, user discount, production polling schedule, source switching, paid quota cap or marketing behavior was changed. Photo fallback, ambiguous timeout quarantine and paid/manual access remain normal delivery policy. The separate delivery audit owns any changes to `worker.py` and its tests.
