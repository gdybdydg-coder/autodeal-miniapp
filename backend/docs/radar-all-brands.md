# Усі марки та порядок за популярністю

У редакторі радара «Усі марки» охоплює всі марки й моделі. Ціна, області,
роки випуску та мінімальна вигода залишаються незалежними обмеженнями.
Вибір окремої марки вимикає режим усіх марок. Перехід до всіх марок очищає
попередні обмеження моделей. Чинні радари самостійно не змінюються.

API явно приймає `all_brands: true` разом із `brands: []`. Порожній список
без явного режиму, як і одночасне передавання всіх та окремих марок,
відхиляється. Для старих клієнтів `all_brands` за замовчуванням `false`;
ідемпотентні повтори створення старих конфігурацій залишаються сумісними.

У нормалізованих таблицях відсутність вибраних марок означає всі марки,
так само як відсутність вибраних областей означає всю Україну. Потрібна
одна похідна гілка пошуку без обмеження марки та моделі. Нових таблиць,
міграції або сотень гілок за каталогом немає. Власність, підписка, пауза,
відстеження змін конфігурації та захист від повторних повідомлень збережені.

Запит усіх марок може обслуговувати також радари окремих марок/моделей,
коли решта параметрів відкриття оголошень однакова. Для кожного радара
локально застосовуються його власні критерії. Інші області, роки чи ціни
не об'єднуються цим правилом. Ширший пошук природно може мати більше
сторінок та оцінювань; чинні квоти й пагінація залишаються обов'язковими.

Порядок марок задає перевірений знімок публічного селектора AUTO.RIA у
`backend/data/radar_brand_popularity.json`. Джерело й час перевірки записані
в ньому та доступні в `brand_order` відповіді каталогу. Каталог не робить
зовнішніх запитів при відкритті форми. Марки, що з'являться після знімка,
не зникають: вони відображаються після ранжованих марок. Оновлення знімка
потребує окремого випуску; це не рейтинг у реальному часі.

Випуск: спочатку backend із підтримкою обох режимів, потім новий frontend.
Перед відкатом врахуйте нові радари з усіма марками: старий backend не вміє
їх компілювати. Віддавайте перевагу виправленню вперед, зберігайте
конфігурації, підписки, квоти й історію повідомлень. Не відновлюйте стару
копію бази поверх нових користувацьких даних.
