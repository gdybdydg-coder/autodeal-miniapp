AutoDeal — сортування, контроль повноти та перевірка30 детальних карток
07.10.2026; продовження погодженого плану. Локальний ізольований дослід.

Головний результат
Ціна/характеристики суттєво просунулися:30/30 перевірених детальних сторінок
успішно розібрано; ціна JSON-LD збіглася з основним видимим HTML-блоком30/30.
Повного безкоштовного пошуку вигідних авто ще немає: незалежний малий
контроль знайшов1/3, готових ринкових оцінок0/30, Telegram-відправлень0.

Використано з попередньої роботи
Гілка wip/free-search-evidence-20261007, початкова точка6f203ec;
public_search_state/public_details/valuation та збережені публічні HTML.
Контрольні ID40533916/40533903/40533902 зберігаються в історії; причину їх
попередніх пропусків не оголошуємо встановленою. Відсутнє handoff-вкладення
не прочитане; правила поточного повідомлення та плану дотримані.

Етап1: сортування і незалежний контроль
У видимій формі підтверджено order=7 «Дата додавання», republished_last=1
«За годину». Раніше використаний order=0 позначений «Звичайне».
Перевірено3 сторінки нового публічного /uk/search/, page0/1/2, limit20,
order7. Значення order7 підтверджене повернутим станом форми та searchString.
Отримано60 карток,58 унікальних ID. Самі20карток не доводять повноту джерела.
До цих GET зафіксовано всі3 унікальні ID зі старих production-логів accepted
за21:01–21:11 Київ (18:01–18:11UTC). Нових платних запитів для контролю немає.
Контроль незалежний від видачі прототипу, але упереджений клієнтськими
фільтрами та успішним платним оцінюванням. Це не безкоштовне джерело роботи
майбутнього збирача і не репрезентативний контроль усього ринку.

1/3 — тільки перекриття цього малого контролю. Не називати це recall ринку.
Сторінку0 повторено через86.895с між завершеннями: HTML побайтово однаковий,
SHA256 той самий, Date заголовка змінився. Це сигнал перевірити кешування/
свіжість; не доказ конкретного TTL або гарантованої затримки87с.
Достовірного publication_at чи першої доступності джерела немає. Написи
«Декілька секунд тому» не перетворювали на точний timestamp. Старі ID у
свіжій видачі не є самостійним доказом першої публікації чи перевиставлення.
Найкращий перевірений кандидат для наступного досліду: публічний search
з явно заданими order7, limit20 та перевіркою повернутих параметрів;
виробничо придатним і повним збирачем його ще не вважаємо.

DOM-звірка читає текст основних ID із HTML, а не виконує браузерний рендер.
Це узгодженість двох представлень однієї сторінки, не перевірка продавця.
Кузов «Легкові» з JSON-LD не використовується як тип кузова. Дані беруться
з окремого підписаного блоку; engine_cc не вгадується за моделлю.
Місячні платежі/лізинг відокремлені від основного цінового блоку.
Картки з дефісами у slug тепер приймаються зі збереженням звірки ID/домену.
У двох JSON-LD неповні додаткові поля:40534169 fuel відсутній;
40534070 fuel/transmission відсутні. Електричному авто не вигадували літраж.
Обмеження: усі30 активні за заявою джерела і мають USD у JSON-LD. EUR/UAH-
основні ціни та неактивні сторінки ще не перевірені live. Етап2 не закрито
лише через досягнення числа30. Потрібні також відкладені перевірки парсера.

Етап3: дві альтернативи безкоштовної оцінки
А. У30 сторінках знайдено прив’язане до autoId averagePrice з кнопки
«Середня ціна». Воно зчитане з уже отриманого HTML, без bff/API/кліків.
Для Subaru40534272 публічне averageRaw20713, тоді як наявний платний лог
о21:10:56 містив average_usd20391. Публічна сторінка отримана о21:14:29.
Різниця322 і різний час не дозволяють довести ні тотожність, ні причину
розбіжності. У самому hint немає підтверджених currency/range/quantity/
period/as_of. Валюту сусідньої asking price не переносили на hint.
Чинна формула потребує діапазону; avgValueRange0.05 із paid logs не
підставляли. Доданий адаптер повертає hint_only, market=null, ready=false.
Висновок А: безкоштовний еквівалент погодженої оцінки НЕ підтверджено.
Б. Запущено існуючу експериментальну peer-модель тільки на цих30 свіжих
публічних деталях, з кузовом/двигуном/поколінням, коли вони відомі.
Платні оцінки/hint у модель не передаються; застосовано allowlist полів.
Своє ID виключається з аналогів. Результат0estimated/30unknown:
всі30 — too_few_comparable_peers. Широка вибірка марок перевіряє парсер,
але не створює густу базу сумісних аналогів. Цей запуск не є незалежним
holdout і не перевіряє якість ринкової моделі. Формулу не змінено.
Наступна альтернатива: цільова база аналогів у3 сегментах після read-only
звірки поточних фільтрів; зафіксувати holdout до підбору/калібрування.
Не розширювати сумісність лише для штучного зменшення unknown.

Код, тести, продовження
Додано embedded_state.py (без виконанняJS; duplicate/nonfinite JSON guard),
public_average_hint.py, public_detail_crosscheck.py і регресійні тести.
public_search_state використовує спільний decoder; public_details підтримує
дефіси в slug. Зміни тільки experiments/free_search, жодних backend-змін.
279 unittest тестів PASS, git diff --check PASS. Code saved in isolated branch;
це не впровадження в основний AutoDeal. WIP-гілку цілком у main не зливати.

Далі в межах наявного дозволу:
1. Перевірити глибину/рухомі межі та source freshness на новому незалежному
контролі; зберігати1/3 як результат цього тесту, не підмінювати новою вибіркою.
2. Доповнити live парсер-контроль неактивними та іншовалютними сторінками,
провести відкладену перевірку. Не вважати мінімум30 повним покриттям випадків.
3. Цільові безкоштовні аналоги і незалежний holdout; public average hint
лишається лише дослідницьким полем, не підставою клієнтського повідомлення.
4. Тільки після доказової оцінки — isolated end-to-end без Telegram.
Будь-який Render shadow із новим ресурсом/конфігом — окреме погодження;
production/source switch та відправлення — ще одне явне погодження.
Production/main/DB/env/оплата/реклама/розклад/OLX не змінювалися.
Фонових задач не створено.
