# Незалежна перевірка повноти та якості: інструмент

2026-10-02, продовження після dbd8de0. Новий evaluation.py працює тільки з
локальним JSON, не виконує HTTP, не читає production DB і не надсилає повідомлення.

## Результат цього етапу

Підготовлено інструмент для порівняння отриманих карток з окремою контрольною
вибіркою. Старий replay.compare_control лишається простим offline-порівнянням;
для звіту з provenance, якістю й затримкою використовувати evaluation.

- Вхід вимагає kind synthetic/observational, незалежний метод і reference,
  окремий collector_run_ref, часові межі та ознаку завершення обходу.
- Однаковий reference збирача й контролю відхиляється. Незалежність походження
  декларується людиною і не може бути доведена програмно лише двома різними назвами.
- Підрахунок за source+ID: точні повтори не множаться, конфліктні записи відхиляються.
- Recall виявлення рахується тільки всередині контрольної вибірки, ніколи не
  називається повним охопленням OLX, навіть за collector_complete=true.
- Якість: TP/FP/TN/FN для визначених результатів; unknown, неоцінені та пропущені
  виділено окремо. Загальна recall вигідних включає ВСІ позитивні контрольні мітки,
  зокрема пропущені та невизначені. Не можна приховати їх із знаменника.
- Це end-to-end рекомендації за обраним сценарієм, не ізольована точність формули.
  Контрольні мітки мають відповідати однаковим фільтрам/вікну/порогові вигідності.
- Precision розраховується тільки на розмічених прикладах; рекомендації без
  незалежної мітки показуються окремо. Ціни пропозицій не є цінами продажу.
- p50/p95 затримки рахуються тільки для перевіреної дати публікації та невід'ємного
  інтервалу до detected_at. Немає дати — null, а не вигаданий нуль секунд.
- Межі напіввідкриті [start,end), у результаті UTC та Europe/Kyiv з offset.
- Вихід містить лише агрегати: ID карток і provenance reference не публікуються.
- Вхід <=2MiB, один запуск, без фонових процесів. Порожній контроль → recall null.

## Як підготувати справжню контрольну вибірку

Після погодження каналу: зафіксувати регіони, категорію легкових авто, фільтри,
часове вікно та джерело незалежного контрольного списку до оцінювання збирача.
Контроль не експортувати з цього ж збирача. Потрібні source/id, recorded_at,
окремо підтверджений published_at, незалежна profitable=yes/no/unknown з доказами.
Розмітку проводити без перегляду рішення алгоритму; сумнівні мітки не форсувати.
Результат збирача: detected_at, processed, valuation, filter_match, recommended.
Уточнити затримку появи у джерелі й достатній горизонт очікування після вікна:
поточний evaluator вимагає виявлення всередині заданого вікна й не вимірює
late arrivals окремо. Повторити для кількох періодів і регіонів, зазначити спосіб
відбору та можливу упередженість. Перший convenience sample не є всім ринком.
