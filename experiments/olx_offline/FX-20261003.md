# OLX: USD-нормалізація, 2026-10-03

## Що додано зараз

Ізольований `fx.py`, 17 цільових тестів у `test_fx.py` і збережений результат
однієї реальної перевірки НБУ. Production, AUTO.RIA, підписки й Telegram не змінено.
Модуль не виконує HTTP, не читає `.env`, не запускає таймер і не відкриває робочу БД.

Публічний контракт:

```python
quote = parse_nbu_quote(raw_json, requested_date="2026-10-03", fetched_at=aware_datetime)
normalized = normalize_price({"price": "210 000", "currency": "UAH"}, quote, now)
```

Результат містить `status`, `reason`, `original_amount`, `original_currency`,
`usd_amount`, `fx` і `conversion_precision`. `fx` містить курс UAH за 1 USD,
документоване джерело, дату дії, час отримання і окрему дату розрахунку НБУ.
Для USD немає конвертації, `fx=None`. EUR/невідома валюта залишаються `pending`.
Якщо курсу немає або він непридатний, початкова сума зберігається для повторної
обробки; гривнева сума не видається за доларову.

Формула: `USD = UAH / UAH_per_USD`. Значення зберігаються десятковими рядками.
Ділення використовує `Decimal` з 50 значущими цифрами: немає округлення до центів
перед порівнянням. Для нескінченного десяткового дробу це задокументована точність,
а не твердження про математично скінченний результат. Початковий чисельник і курс
зберігаються. Округлення до цілого долара робить лише `display_price`, зі знаком
`≈` для перерахованої гривневої суми. Довідковий курс не гарантує курс банківського обміну.

Приймаються пробіли/NBSP як розділювачі тисяч, десяткова кома/крапка,
однозначні змішані форми на кшталт `210,000.00` і `210.000,00`.
Неоднозначне `1,234` або `1.234` у зовнішньому тексті затримується для перевірки;
ця політика запобігає мовчазній помилці у 1000 разів. Числа `float`, нуль, від'ємні
значення, NaN і некоректні рядки не допускаються. Парсер JSON НБУ читає `float`
токени через `parse_float=Decimal`.

Повторний виклик використовує збережені `original_*`, тому повторно не ділить уже
перерахований USD. Заміна курсу перераховує саме початкову суму продавця. Інтеграція
має порівнювати `Decimal(usd_amount)` та відокремлювати зміну курсу від зміни ціни
продавцем; цей модуль самостійно не змінює чергу або fingerprint оголошення.

## Перевірене офіційне джерело та межі

Документація НБУ:

- https://bank.gov.ua/admin_uploads/article/Instr_API_KURS_VAL_data.pdf
- https://bank.gov.ua/admin_uploads/article/Instr_API_KURS_VAL_data_Full_eng.pdf

Індексований текст офіційних документів підтверджує GET:

`https://bank.gov.ua/NBU_Exchange/exchange_site?start=YYYYMMDD&end=YYYYMMDD&valcode=usd&sort=exchangedate&order=desc&json`

Використовується одна дата `start=end`, код USD/840, `units=1` і
`rate_per_unit`; перевіряється узгодженість з `rate`. `exchangedate` є датою дії,
`calcdate` зберігається окремо. Офіційні приклади включають вихідний 01.05.2022
з попередньою датою розрахунку: це підтримує явну дату дії на вихідний, а не
самовільне продовження п'ятничного кешу. Приклади документації історичні,
не використовуються як поточний курс. Повний PDF та сторінка API у web-інструменті
повертали HTTP 403; доступними були індексовані фрагменти офіційного документа.

Час і календарна дата беруться за `Europe/Kyiv`. Підходить лише курс з точною
поточною київською датою дії. Завтрашній курс не можна застосувати сьогодні,
навіть якщо його вже оприлюднили. П'ятнична дата дії не переноситься на суботу
автоматично. Курс на суботу з датою розрахунку у п'ятницю може використовуватися,
якщо НБУ явно вказує суботу як `exchangedate`.

Спільний `FXCache(explicit_local_path)` зберігає одну котировку на дату у SQLite
і переживає перезапуск. Отримання курсу виконує зовнішній координатор один раз для
пакета; модуль не запитує валюту для кожного оголошення. Граничний вік кешу за
замовчуванням 86400 секунд, його можна зменшити. Зміна дати за Києвом робить
попередню дату непридатною раніше цього ліміту. Майбутній час отримання також
відхиляється. За помилки API система очікує придатний курс, без констант і
непомітного запасного джерела.

## Єдина пряма жива перевірка

Файл доказу: `evidence/nbu-probe-20261003.json`.

- UTC: 2026-10-02 21:39:07.820989–21:39:07.988365.
- Київ: 2026-10-03 00:39:07.820989–00:39:07.988365 (+03:00).
- Запитана дата дії: 2026-10-03.
- Один GET, timeout 20 секунд, обмеження тіла 256 КіБ, без повторів і перенаправлень.
- Результат: **пряма HTTP-відповідь 403**, 0.167 секунди. Тіло помилки не збережено.

Це результат запиту через поточне середовище. Він не доводить, що обмеження
встановив саме НБУ, і не доводить недоступність API для інших середовищ.
**Поточний курс не отримано. Живий перерахунок гривневих оголошень не підтверджено.**
Фіксованого запасного курсу немає; результат для таких оголошень — `fx_missing`.
Не виконувалися інші запити до валютного API для обходу цієї відповіді.

## Перевірки

```bash
python -m unittest experiments.olx_offline.test_fx -v
```

17/17 тестів пройшли: напрямок ділення; USD без курсу; повторна конвертація;
точність і округлення лише відображення; розділювачі; неправильні суми/валюти;
відсутній курс; вихідні; дата Києва біля півночі; майбутні дата й час;
застарілий кеш; схема НБУ; збереження кешу й 200 повторних локальних обробок.

Курс 42 і решта курсів у цих тестах **вигадані**, використовуються лише для
арифметики. 210000 / 42 = 5000 не є твердженням про курс НБУ на дату роботи.
Не завершено: отримання реальної чинної котировки, вимірювання стабільності
безкоштовного валютного каналу, production-інтеграція. Реальну котировку потрібно
одержати у доступному дозволеному середовищі, перевірити схему/дату і зберегти
з provenance; до того моменту UAH-оцінювання залишається невизначеним.
