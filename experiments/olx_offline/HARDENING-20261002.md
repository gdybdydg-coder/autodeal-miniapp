# Продовження OLX: актуальність і безпека черги

Дата: 2026-10-02. Це нова робота після commit d84a4e9, не повтор попереднього звіту.
Production/main/AUTO.RIA/платежі/підписки не змінювалися. Модулі залишаються offline.

## Виправлені ризики

1. **Ціна змінилася після enqueue.** Раніше sender читав нову картку, але рішення
   про вигідність було старим. Тепер delivery_proof зберігає fingerprint суттєвих
   полів і строк дії. Зміна картки або вік рішення понад 300 секунд →
   needs_revalidation, без виклику sender. Повторний enqueue переоцінює картку
   та фільтри; прийняті/невизначені доставки не повторюються. 300 секунд —
   дослідницька межа, потребує погодження після вимірювання live потоку.
2. **Давність ціни порівняння.** first_seen більше не є доказом її актуальності.
   estimate вимагає checked_at; без нього, з майбутнім або простроченим часом
   порівняння не використовується. Ціна старого оголошення може бути використана
   після свіжої перевірки. Дата має походити від майбутнього довіреного адаптера,
   а не від довільного користувацького JSON; такий адаптер ще не створено.
3. **Цикл cursor між перезапусками.** Відвідані cursor зберігаються разом із
   сторінкою в SQLite. Цикл між кількома запусками не створює нескінченних запитів.
   При початку наступного повного обходу історія cursor очищується.
4. **Стара черга без доказів.** Pending із попереднього формату не відправляється
   без переоцінки. Schema extension локальна й additive; production DB не відкривалась.
5. **Некоректна картка.** Значення не-об'єкт зупиняє сторінку як incomplete,
   не пересуваючи checkpoint і не видаючи неповний обхід за успішний.
6. **Повторні спроби.** Після успішної сторінки лічильник послідовних помилок
   коректно обнуляється. Додано індекси статусів черги та eligibility.

Snapshot не є транзакцією з віддаленим продавцем: зміна ціни вже після останньої
перевірки все ще можлива. Live re-fetch, TTL порівнянь, batching та rate limits
залишаються окремими гейтами. Однопроцесний SQLite, не concurrent worker.

## Нові докази джерела

Знайдено та прочитано офіційний OpenAPI файл:
https://developer.olx.ua/swagger/v2/partner_api.yaml
Він описує OAuth і контекст користувача для оголошень; client_credentials
призначено для конфігураційних довідників, наприклад категорій/міст.
Це доповнює попередню перевірку оболонки api/doc, але не відкриває пошук усіх продавців.
FAQ знову підтверджує обмеження власними оголошеннями:
https://developer.olx.ua/ua/articles/faq

Нових API-викликів до OLX не робили; читали документацію через web.
Живий загальноринковий канал, актуальні правила публічного збору, незалежна
контрольна вибірка та точність оцінювання залишаються непідтвердженими.
Реєстрації застосунку/отримання ключів/запитів від імені власника не було.

## Перевірки цього продовження

37/37 тестів, із них 9 нових регресійних:
- зміна ціни → hold → повторна оцінка;
- прострочене рішення → hold;
- свіжий checked_at без зміни ціни не створює хибний hold;
- стара pending без proof не надсилається;
- first_seen не замінює перевірку ціни;
- старе оголошення зі свіжою перевіркою допускається;
- старі та майбутні checked_at відкидаються;
- cursor-cycle виявляється після restart;
- некоректна картка не завершує обхід.

Повторно виконано весь synthetic flow (240 карток, 12 сторінок):

| Користувачів | Нормалізація/SQLite | Оцінка/фільтри/черга | Fake delivery | Разом | Python peak | SQLite |
|---|---:|---:|---:|---:|---:|---:|
| 100 | 0.030с | 2.042с | 5.460с | 7.531с | 3.49MiB | 3.25MiB |
| 200 | 0.030с | 4.019с | 10.559с | 14.608с | 6.82MiB | 6.36MiB |

180/240 карток пройшли синтетичний поріг, 60/240 не пройшли;
18000/36000 fake accepted; після restart повторно додано0. Proof та індекси
збільшили час/розмір проти попереднього заміру: це явно враховано, не приховано.
Дані: evidence/synthetic-hardening-results.json. Не SLA та не Telegram throughput.
Стара evidence/synthetic-results.json збережена як історичний вимір.
Синтетична оцінка якості не змінилась: 10/100 unknown; реальна якість невідома.
Мережевий socket у тестах/benchmark заблоковано. Платних API/Telegram запитів0.

## Відтворення й наступні гейти

```sh
python -m unittest discover -s experiments/olx_offline -v
python -m experiments.olx_offline.scenario
```

Потрібні погоджений канал даних і реальні sanitized fixtures. Після цього:
реальна класифікація категорії/ціни/дат → незалежна контрольна вибірка →
калібрування FP/FN/unknown → isolated стенд на актуальному main → погодження
власника → обмежений opt-in запуск. OLX default disabled; робочий бот не підключений.
Перед публікацією знову перевірено Render: main, autoDeploy yes, previews off.
Workflow файлів у дослідницькому дереві немає; нових workflow не додано.
