## Нічний виконавець, збереження та зупинка

Дані запуску і реальний automation ID записуються в `night-state.json` після
підтвердження створення задачі. До такого підтвердження незалежна нічна робота
не вважається запущеною. Задачі інших напрямів і нагадування не змінюються.

Кожен цикл максимум 30 хвилин і до абсолютної межі 08:00 Kyiv. До 4 прямих OLX
GET / 8 MiB та 1 НБУ GET / 256 KiB; timeout≤20s, пауза≥5s, без автоматичних
redirect/retry. 401/403/429 зупиняють запити цього джерела; не повторювати відому
відмову без нових обставин. Прямі запити — спільні, не для кожного користувача.
Шість запланованих циклів мають верхню межу 24 OLX GET / 48 MiB, не ціль витрати.
НБУ на ніч не опитувати повторно лише заради статусу після зафіксованого 403.

Взаємне виключення між машинами:
1. Прочитати remote HEAD і `night-state.json`; STOP або чинна lease → без роботи.
2. `lease.claim` готує token/expiry. Створити commit із **саме цим HEAD** як parent,
   оновити лише дослідницьку гілку з `force=false`. Програш гонки → без роботи.
3. Перед мережевою операцією/публікацією перевіряти актуального власника lease.
   Старий власник після expiry не має права публікувати; чужі зміни не перезаписувати.
4. Записати код/тести/докази/наступну задачу й звільнити свою lease одним завершальним
   commit через non-force update. Втрата доступу → залишити результат у історії задачі.

Локальний `RunGuard` додатково забезпечує flock, STOP-файл і кооперативні бюджети.
Він не є міжмашинним lock і сам не запускає фонового процесу. Жоден watchdog не
оголошено працюючим без виконавця. Щоб зупинити: вимкнути задачу за її ID; для
поточного локального probe створити STOP у його приватній папці; для всієї серії
встановити `stop=true` в night-state. Перевірка відбувається між операціями, активний
HTTP обмежений своїм timeout; зупинка не перезапускає Render.

```sh
python -m experiments.olx_offline.scenario
python -m experiments.olx_offline.bounded_probe --help
python -m experiments.olx_offline.run_guard inspect --help
```

Публічні HTTP-перевірки потребують явного `--allow-network` і приватної scratch-папки
поза checkout. URL беруться тільки з реально побачених посилань або офіційної
документації. Сирі HTML містять зайві дані і не публікуються. Production app/env
не запускати. Tests/scenario використовують тимчасову SQLite та забороняють socket.

Пріоритети наступних циклів — `night-state.json`: легітимна пагінація/новизна,
невелика незалежна вибірка активних повних описів і ціни, реальні порівняння,
перевірка ізольованих адаптерів/ресурсів, ранкове підбиття результатів. За блокера
джерела виконувати незалежний пункт; не повторювати одну невдалу спробу всю ніч.

Очікувані робочі запити = сторінки спільного обходу + нові/прострочені деталі +
оновлення курсу на дату. Числовий добовий прогноз поки неможливий: фактична
швидкість появи, межа видачі та придатний інтервал не виміряні. Витрат нових платних
API — 0; витрати CPU/сховища окремі, існуючий Render не навантажувався тестами.

## Умови майбутнього підключення

Перед production потрібні: дозволений стабільний канал і справжня новизна;
достатня реальна оцінка з незалежним контролем; чинний FX; узгоджені ліміти
помилок/затримки; перенесення ізольованих адаптерів на актуальний backend та
перевірка точного diff. Підготовлені модулі не імпортуються production.

Майбутні зміни: перемикач OLX початково off, source choice зі старими пошуками
на AUTO.RIA, окрема OLX-черга/сховище, підтверджений мережевий адаптер, спільна
перевірка доступу/stop перед доставкою, метрики й обмежена тестова група.
Правило AUTO.RIA, оплата, підписки та /stats не змінюються.

Порядок: ізольований стенд → результати й явний дозвіл власника → обмежена група →
спостереження → погоджене розширення. Вимкнення OLX зупиняє його збір і чергу;
AUTO.RIA продовжує працювати. Відкат — повернути лише погоджений OLX integration
commit, не стираючи історію доставки та не змінюючи production-платежі.
До виконання цих умов не просити дозвіл на непідготовлений запуск.
