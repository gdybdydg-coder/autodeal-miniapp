# Технічний запит до OLX щодо автомобільних оголошень

**Чернетка, не надіслано. Потребує погодження власника.**

Підготовлено: 03.10.2026.

Офіційний контакт: https://developer.olx.ua/ua/contact. Перевірена сторінка пропонує ввійти для звернення до технічної підтримки API; звернення та вхід від імені власника не виконувалися. Адреса електронної пошти не встановлена.

Офіційний FAQ, пункт 6, обмежує Partner API власними оголошеннями авторизованого облікового запису: https://developer.olx.ua/ua/articles/faq. Тому стандартний доступ до цього API не вважаємо дозволом отримувати оголошення всіх продавців. Письмового погодження регулярного збору публічних сторінок немає.

---

Вітаємо! Ми розробляємо AutoDeal — Telegram-бот, який відбирає автомобільні пропозиції за фільтрами користувачів та оцінює їхню вигідність. Хочемо погодити отримання легкових автомобілів з OLX як другого джерела й показ карток із посиланням на оригінальне оголошення. Зараз дослідження ізольоване від робочого бота, оголошення OLX клієнтам не надсилаються. Нам відоме обмеження Partner API власними оголошеннями. Просимо уточнити окремий придатний канал та його умови:

1. **Канал і дозвіл.** Чи доступні для нашого сценарію погоджений feed, API або export легкових автомобілів усіх продавців? Якщо такого каналу немає, чи можна отримати письмовий дозвіл на обмежене читання публічної HTML-видачі та сторінок оголошень із загальним для всіх користувачів збором, кешуванням, timeout, обмеженням запитів і негайною зупинкою за блокування або перевищення лімітів? Які умови та порядок погодження застосовуються?

2. **Новинки та дати.** Як отримувати сортування саме за першим створенням або першою публікацією, незалежно від платного підняття й редагування? Які поля й часовий пояс відрізняють створення, публікацію, редагування та підняття? Чи зберігається ID після повторної публікації та як відрізнити її від підняття?

3. **Пагінація, повнота й частота.** Чи є стабільний cursor, послідовність подій або інший спосіб обходу без пропусків при появі нових оголошень між сторінками? Які доступні глибина й строк історії, максимальні обсяги відповіді, ліміти запитів і рекомендована частота перевірок? Яка документована або вимірювана затримка появи публікації в каналі, та як канал повідомляє про неповний результат, видалення й завершення обходу?

4. **Поля, фото, показ і зберігання.** Які поля дозволено отримувати й зберігати: ID, URL, заголовок, ціна та валюта, характеристики автомобіля, область/населений пункт, дати й фотографії? Чи дозволений показ короткої картки та фото з позначкою «OLX» і переходом на оригінал у комерційному Telegram-боті з платною підпискою? Які вимоги до атрибуції, кешування фото, строку зберігання, оновлення та видалення даних? Контакти, профілі продавців та інші персональні дані ми не плануємо збирати.

5. **Порівняння цін.** Чи дозволено накопичувати неперсональні характеристики та ціни оголошень для порівняння відповідних моделей, поколінь, років, двигунів, коробок, кузовів і пробігу? Ми показуватимемо власний розрахунок за цінами пропозицій, не видаватимемо його за оцінку OLX або підтверджену ціну продажу. Які обмеження на історію, агреговані результати та комерційне використання застосовуються?

6. **Вартість і підтримка.** Які тарифи, умови договору, тестовий доступ, підтримка та SLA доступні для погодженого каналу? Просимо також описати порядок повідомлення про зміни схеми, обмежень і припинення доступу. Це запит інформації та умов; замовлення, оплата або прийняття платних зобов’язань потребуватимуть окремого погодження власника AutoDeal.

Дякуємо! Просимо надати відповіді та посилання на чинні умови, а якщо питання виходять за межі підтримки Partner API — підказати офіційний підрозділ або процедуру погодження такого сценарію.
