## Збір, ціна, збереження

`canonical` приймає НАШ явний контракт, не видає його за OLX JSON. Значення
категорії whole_passenger_car і price_kind=full має довести майбутній parser.
Частини/rental/service/wanted не проходять як цілий автомобіль. Стан damaged
не блокує авто. Невідома повна ціна, платіж/аванс/умовна ціна залишають оцінку
непідтвердженою. Визначення цих ознак із реального тексту ще не реалізоване.
Валюти не змішуються. FX навмисно відсутній: для майбутнього перерахунку потрібні
джерело, дата/час курсу, політика давності та тести; вигаданих курсів немає.

Стартова межа t0 зберігається до першого fetch. Перевірена публікація >=t0
потрапляє у новинки навіть під час baseline; старі й неперевірені дати зберігаються
окремо. updated/bumped не є публікацією. Відомий старий ID не стає новим через
підняття; first_seen зберігається. Ціна може оновити картку, але не створює повторної
доставки. Політика повідомлення про зміну ціни потребує погодження.

Кожна сторінка і cursor записуються однією транзакцією. Page/row budgets явні;
досягнення межі — incomplete, last_success не пересувається. Timeout зберігає
попередні сторінки та час повторної спроби з capped backoff; після перезапуску
продовження з cursor. Після 3 помилок потрібен ручний перегляд; нескінченних повторів немає. Черга переповнюється без видалення картки, повторний enqueue
може додати її після звільнення місця. Невідомі оцінки залишаються у listings.

**Обмеження:** нестабільна offset-пагінація реального OLX, глобальний порядок і
late indexing ще не досліджені. Cursor expiry і multi-process locking не вирішені.
Довіряти complete можна тільки в межах наданого fixture/export контракту, не всього
OLX. При невідомій даті неможливо гарантувати відсутність стартових пропусків.
Контролер HTTP403/429/CAPTCHA має припиняти live обхід; мережевого адаптера наразі немає.

## Вигідність: метод і результати

Порівнюються model/generation/body/fuel/transmission/engine_cc точно, рік ±1,
пробіг ±30000 км. Це початкові дослідницькі параметри, не відкалібровані допуски.
Однаковий source+ID і підтверджений vehicle_key не дають подвоєння порівнянь;
відкидаються старі (>30 діб за first_seen) і майбутні записи. Live адаптер має
додати час останньої перевірки актуальності ціни: first_seen для цього недостатньо.
Мінімум 8 порівнянь після IQR-фільтра, діапазон <=40% медіани. Експериментальний
орієнтир Q25×0.95; користувацький discount застосовується окремо. Це власний
розрахунок цін пропозицій, НЕ оцінка AUTO.RIA і НЕ фактична ціна продажу.
Чинне правило AUTO.RIA та її код не змінювалися.

Holdout 100 синтетичних цілей із наперед заданими ринковими сценаріями:
- Строге порівняння: TP40, FP0, TN50, FN0 серед визначених, unknown10.
- Усі 10 unknown були вигідними за синтетичною міткою: фактична втрата
  рекомендацій 10/50=20%, recall із включенням unknown=80%, не 100%.
- Навмисно змішана широка вибірка «марка+рік»: TP50, FP50, TN0, FN0.
Це демонстрація ризику змішування моделей, не незалежне доведення переваги формули.
Дані прості; на реальних пошкоджених/рідкісних авто помилки й unknown можуть бути
значно більшими. Частка невизначених на реальному потоці НЕ виміряна.

## Інтеграція та дублі

Вибір джерела підготовлено чистою функцією; старі пошуки default auto_ria.
UI в робочій Mini App не змінено. Filters bridge переводить mileage тис.км → км,
зберігає кілька регіонів та minDiscount, вимагає явну валюту бюджету. Числові ID
не переносяться між платформами; таблиця назв лише fixture-словник, повні офіційні
довідники не підтверджені. Відсутні fuel/transmission не суперечать фільтру,
але можуть залишати оцінку невизначеною.

Access adapter має використовувати ті самі billing.allowed, User.ready і
Search.enabled, перевірені перед enqueue і перед доставкою; fixture використовує
paid/stopped та injected access callback. Це не повний production integration test.
Немає обходу доступу через окремий OLX endpoint. OLX default disabled.

Ключ доставки uid+source+id. sending записується до fake sender; тільки True
дає accepted. Timeout і незавершене sending після restart → uncertain без автоповтору.
accepted означає прийняття симулятором, не прочитання. Реального sender немає.
Схожі назва/рік/ціна — тільки можливий дубль, обидві картки зберігаються.
Підтверджений vehicle_key дає review, не автоматичне приховування іншої ціни.
Реальні кроспости та доказове отримання vehicle_key ще не перевірені.

## Відтворення

Python 3.11+, тільки stdlib; запуск із кореня дослідницької гілки:

```sh
python -m unittest discover -s experiments/olx_offline -v
python -m experiments.olx_offline.scenario
python -m experiments.olx_offline.replay --help
```

Не запускати backend.app, production .env, worker або моніторинг.
scenario створює тимчасову SQLite, блокує socket і видаляє її після вимірювання.
Тестові приклади та порівняння генеруються заново; оплачений кеш не читається.

Для погодженого збереженого export:
```sh
python -m experiments.olx_offline.replay --export pages.json --control independent.json --database isolated.sqlite --now 1790942400 --pages 5 --rows 200
```
pages.json: об'єкт із ключем start та наступними cursor, сторінка {items:[...],next:null|string}.
independent.json: масив {source,id}, отриманий незалежно від збирача із зазначеним
походженням поза публічним repo. Кожен input <=2MiB. Це offline replay, не живий crawler.
Для тривалих спостережень повторювати вручну з новими дозволеними export і тим самим
DB; зберігати вікно UTC/Kyiv, пропуски, overlap і причини. Фоновий виконавець не запущений.
Перед майбутнім live: окремо погодити канал; початковий бюджет до 5 GET/5 хв,
пауза >=10сек, timeout20сек, cap2MiB загалом, без повторів 403/429/CAPTCHA;
частоту змінювати лише за виміряним потоком і дозволом каналу.

## Ресурси: лише сценарні оцінки

Спільний збір не множить OLX GET на кількість користувачів. Для P сторінок,
D detail/cache misses на цикл та інтервалу T хв: GET/day=(P+D)×1440/T.
При умовних P=5,D=20,T=5 виходить 7200/day; це НЕ дозволений бюджет і НЕ виміряний
потік. Detail-fetch, FX refresh і порівняння мають бути включені в майбутній бюджет.
Вартість каналу невідома; безкоштовність повного шляху не доведена.
Окремий server/storage потрібен до production: ціну не вигадуємо і ресурс не купуємо.
Локальний synthetic SQLite близько 2MiB на 240 карток+36000 доставок; приблизний
нахил між двома замірами ~51 байт/додатковий delivery. Це не оцінка фотографій,
індексів production, резервних копій і WAL. Фото не завантажувались/не кешувались.
Зараз enqueue повторно переглядає всі new-картки; потрібен incremental valuation
cache/index і bounded batches перед довгим production-навантаженням. Один процес,
без concurrent writer; resource isolation тільки окремий експериментальний DB/процес.

## Запит до OLX — чернетка, НЕ НАДІСЛАНО

Просимо погодити read-only канал нових оголошень категорії легкових автомобілів
усіх продавців для сервісу сповіщень AutoDeal (100–200 користувачів). Чи доступний
офіційний feed/export або письмово дозволений обмежений доступ до публічної видачі?
Потрібні stable ID/URL, повна ціна/валюта, category, brand/model/generation/year,
engine/body/mileage/fuel/transmission, регіон/місто, фото, окремі created/published/
updated/promoted/deleted timestamps, стабільна пагінація та incremental cursor.
Уточніть сортування, retention/deletions, latency/SLA, rate limits/Retry-After,
права на кешування/показ фото й посилань у Telegram, використання агрегованих
порівнянь цін, строк зберігання, атрибуцію та вартість. Продажі/контакти продавців
не потрібні. Partner API власних оголошень не відповідає цьому сценарію.

## Безпечне підключення та наступні дії

1. Погоджений канал і перевірені умови; активні sanitized fixtures з provenance.
2. Реальний parser, перевірені назви/ціни/дати, stable pagination і backfill overlap.
3. Незалежна контрольна вибірка і розмітка вигідності: FP/FN/unknown, recall,
   p50/p95 етапів; виміряти кілька вікон/регіонів, не тільки одну відповідь.
4. Окремий стенд на актуальному main; справжні production access interfaces
   замінені isolated DB/fake transport; індекси, retention, resource budgets.
5. Показати докази власнику → явне погодження → обмежений opt-in запуск →
   спостереження за completeness/unknown/error/overflow → окреме розширення.
6. Kill switch OLX вимикає intake/enqueue/delivery тільки OLX, зберігає pending/
   uncertain; AUTO.RIA продовжується. Відкат інтеграційного commit, без видалення
   журналу/черги. Не змінювати billing, /stats, рекламу та AUTO.RIA.

Перед публікацією перевірено Render: branch main, autoDeploy yes, previews off;
remote tree прототипу не має .github/workflows. Нових workflow не додано.
